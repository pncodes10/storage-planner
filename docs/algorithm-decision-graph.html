Storage Planner · current algorithm

How one file gets its action

Every file ends up retained, deleted or compressed. The decision runs in two steps: first the rules decide which actions are possible for the file, then the planner picks at most one of them, based on how much space you still need.

  • RetainThe default. No option, or the plan did not need it.
  • DeleteOne of 20 rules matched and the planner used it.
  • CompressRe-encode to a smaller format, one fixed setting per type.
  • ArchiveNot reachable for a file today. Only idle apps are archived.

Risk tiers

Every option carries a tier. The tier is its risk, and also its price in the planner.

TierMeaningCostFile actions in it
R0Safe: rebuildable or junk0Delete junk and caches
R1No loss0.5Delete duplicates, trash, re-downloadable copies; lossless screenshots

R3Small quality trade-off3Music to 128 kbps
R4Needs your confirmation5Delete unique items: bursts, blurry, old screenshots, old downloads

Two questions are asked independently, so a file can hold a delete option and a compress option at the same time. Keep is always available and is never written down.

Step 2 · Which option is picked

The need is used space − your target. The planner looks at all files, apps and caches together and picks at most one option per item.

Pick the tier

Try k = R0, R1, … R4. For each k, add up the largest saving every item offers at tier ≤ k. The first k whose sum covers the need is used. Nothing above it is touched.

Greedy pass

Start with every R0 option. List every possible upgrade with its price: extra cost ÷ extra bytes. Apply the cheapest first and stop as soon as the need is met. Big files at a low tier go first.

Prune pass

The greedy pass can overshoot. Walk the chosen options from the costliest per byte and drop each one, or swap it for a cheaper option of the same file, when the plan still covers the need.

Points for our discussion

  1. No file is ever archived. Archive exists only for apps idle 60 days on Android 15. The zip tool is not connected to the planner.
  2. Compress has one setting per type. The video tool's five levels and Motion Photo clip removal are not options the planner can choose.
  3. Many files can't be compressed. HEIC, WebP and AVIF photos, JPEG screenshots, PNGs outside Screenshots and images in Download get no compress option.
  4. Two rules can't fire. The scan skips Android/data, so "App's external cache" and leftovers under that folder are never seen.
  5. Safe junk is always in the plan, even when the target is already met. Everything else is taken only as far as the need requires.
  6. In All safe steps size decides. A duplicate that could also be compressed is deleted, because deleting saves more.
  7. Estimates count like exact bytes. A compress saving of "45%" is a guess, but the planner trusts it as much as a deletion.
  8. Age is the file's modified date. When you last opened a file plays no part.

Apps and caches follow their own short path: cache → clear (R0); idle 60 days on Android 15 → archive (R1); idle 120 days and a game, or Android below 15 → uninstall (R4).
